- Reviewer 可能只关注 import 缺失

## 三、规范完善建议

### 3.1 新增审查规则：PR 描述一致性验证

```
检查项：当 PR 描述声明"移除 X"时，验证代码中是否真的不再使用 X
执行方式：grep 搜索相关符号
```

### 3.2 修改现有规范

| 规范项 | 当前 | 建议 |
|--------|------|------|
| 框架 API 变更 | 只需说明变更 | 必须展示变更前后的关键代码片段 |
| Quick 策略声明 | 未要求 | 强制说明"未覆盖范围"的具体内容 |
| 异常处理 | 未列入检查 | Quick 策略也需提及异常路径处理状态 |

### 3.3 项目特有要点

该仓库是 **AstrBot 插件**，审查时需额外关注：
- 框架版本兼容性声明是否精确
- 是否记录了框架 API 的 breaking change
- bot 属性的获取方式是否健壮（`getattr` vs 直接访问）

## 四、经验教训

### 4.1 警惕 PR 描述陷阱

当 PR 描述说"移除 XXX"但代码仍在使用时，这是一个 **高风险信号**，可能意味着：
- PR 包含多轮修改，部分修改未同步到描述
- 作者意图与实际实现有偏差
- 存在遗漏的回退路径

**审查时**：先 grep 确认描述的"移除"是否真的发生。

### 4.2 规避方案需评估长期影响

本次修复采用了"绕过框架直接调用协议端"的方式。这种方案：
- ✅ 快速解决当前问题
- ⚠️ 丧失框架层封装的优势
- ⚠️ 未来框架升级可能破坏此方案

**审查建议**：应要求作者说明是否计划向框架提 issue，从源头解决问题。

### 4.3 Import 相关问题的快速定位

发现 `MessageChain` 缺失时，正确的审查路径：

```
1. grep -n "MessageChain" 文件   # 定位所有使用点
2. 检查 import 语句            # 确认是否在导入列表
3. 分析使用场景               # 是否确实需要（vs 可用替代方案）
4. 对照 PR 描述               # 是否与声明的变更一致
```

本次审查跳过了第 1 步和第 3 步。
