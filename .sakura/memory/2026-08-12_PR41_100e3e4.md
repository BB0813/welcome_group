## 四、经验教训

### 4.1 值得关注的要点

| 场景 | 关注原因 | 行动项 |
|------|----------|--------|
| 框架绕过式修复 | 暗示框架行为变化具有**扩散性**，可能影响其他 API | 增加间接影响评估 |
| 批量相同修改 | 说明问题可能在设计阶段就存在 | 评估代码重构可能性 |
| event.send() vs bot API | 两种调用路径的行为差异需文档化 | 建议维护 API 兼容性矩阵 |

### 4.2 框架兼容性审查经验

```
框架 API 变更审查检查清单
├── 版本号精确性
│   ├── [x] 精确到 patch (v4.27.2)
│   └── [ ] 说明影响起始版本
├── 全局影响评估
│   ├── [ ] grep event.send() 调用点
│   ├── [ ] grep MessageChain 构建点
│   └── [ ] 评估框架注入行为的触发范围
├── 兼容性策略
│   ├── [x] fallback 机制
│   ├── [ ] 版本判断逻辑（如需要）
│   └── [ ] API 能力检查（hasattr）
└── 测试覆盖
    └── [ ] 建议补充框架版本兼容性测试
```
