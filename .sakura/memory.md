# 代码审查经验积累

> 累计反思 28 次

## 1. 框架 API 变更审查规范

### 必须检查项
| 检查项 | 要求 |
|--------|------|
| 框架版本号 | 精确到 patch（如 v4.27.2），避免 `v4.27.x` 模糊表述 |
| API 签名变更 | 明确参数类型变化（list→MessageChain） |
| 全局扫描 | quick 策略也需说明是否执行 grep 全项目搜索 |
| 向后兼容性 | 评估是否需要版本判断或 fallback |

### Quick 策略边界
```
策略   | 验证范围              | 结论要求
-------|----------------------|------------------
quick  | 修复点+直接影响       | 必须注明"未做全量回归"
full   | 修复点+间接影响+模式  | 提供回归测试建议
```

## 2. Issue 分析标签体系

### 必选标签（框架升级问题）
```markdown
bug                          # 置信度 0.95
framework-compatibility      # 置信度 0.8
regression                   # 置信度 0.85（v4.27.2 版本回归）
needs-review                 # 置信度 0.6（待官方确认）
```

### 标签使用原则
- `enhancement` 不适用于运行时错误
- 框架升级问题**必须添加 `regression` 标签**
- 标签置信度需与证据明确程度匹配

## 4. 代码风格规范

### 字符串格式化
```python
# ✅ 统一使用 f-string
f"错误信息: {e}"

# ❌ 避免 + 拼接
"错误信息: " + str(e)
```

### 类型显式转换
- `user_id` 等字段统一做 `int()` 转换
- `message_list` 构建后验证是否为 list 类型

## 7. 核心经验

| 场景 | 关注要点 |
|------|----------|
| 框架 API 变更 | 版本号精确性、向后兼容性、潜在扩散风险 |
| 批量相同修改 | 暗示复制粘贴或同时引入，评估能否重构 |
| Quick 审查 | 明确边界，避免"看起来没问题"的模糊结论 |
| 测试代码差异 | 框架升级时测试代码也可能受影响 |
| **PR 描述声明"移除 X"** | **必须 grep 确认 X 真的不再使用**，矛盾是高风险信号 |
| **多层 Fallback** | 各路径前置条件、None 显式日志、hasattr vs getattr 差异 |
| **框架绕过修复** | 必须评估框架注入行为扩散范围（如 Reply 组件注入触发条件） |

## 8. 框架问题 Issue 分析模板

```markdown
责任边界：框架/本仓库/用户配置
缓解方案：文档说明/配置指导
替代路径：手动安装/降级建议
标签体系：external-dependency > framework-compatibility（后者仅适用于插件适配场景）
```

## 9. Issue 标签准确性

| Issue 类型 | 必加标签 |
|------------|----------|
| 框架自身 bug | `bug` + `external-dependency` 或 `needs-upstream-fix` |
| 框架升级回归 | `bug` + `regression` |
| 插件适配框架 | `bug` + `framework-compatibility` |

**注意**：摘要协议标签错误不应阻断实质分析；"other"分类门槛极高；可行性"无法评估"应谨慎使用。

## 10. 多层 Fallback 审查清单

```
1. 各路径前置条件是否满足？
2. getattr(obj, None) 后续是否有显式日志记录？
3. None 时是否安全跳过而非静默失败？
4. 旧版本 API 是否存在？是否需要版本检测？
5. 网络异常是否有 try-except 处理？
```

## 10. 常用 grep 关键词

| 搜索目标 | 关键词 |
|----------|--------|
| Reply 组件 | `Reply(` 或 `MessageChain([Reply` |
| event.send 调用 | `event\.send(` |
| MessageChain 构建 | `MessageChain(` |
| PR 描述验证 | `grep -n "SymbolName" file.py` 验证"移除"声明 |
