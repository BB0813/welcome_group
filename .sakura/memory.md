# 项目记忆 · welcome_group

累计反思 5 次

## 项目画像
- 群欢迎/退群/被踢提示插件，单文件 `main.py`（约 500+ 行），配置驱动
- 基于 NoneBot 类框架（AstrBot），命令注册不支持 `command_group` 嵌套
- LLM 集成：`self.context.llm_generate`，有启用开关 + 模板回退
- 配置字段约定：**事件类型前缀式**（`leave_message`/`kick_message`），非后缀式

## 核心审查规则（项目沉淀）

| ID | 规则 |
|----|------|
| R-DR-01 | ≥2 个结构相似度 >80% 的 handler 必须抽取公共函数 |
| R-F541 | f-string 必须含至少一个 `{...}` 占位符（建议 ruff F541） |
| R-EVT-EMPTY | 事件处理器读取模板/配置后必须做空值校验，防群内空白消息 |

| R-NAME-01 | 命令命名与既有家族（`test`/`test_leave`）保持一致 |
| R-DOC-01 | 命令名变更必须同步 README/docs；PR 模板加 checklist |
| R-REFACTOR-PARAM | 重构抽取公共函数时，所有差异化维度（语气/错误文案/日志标签）必须参数化 |

| R-TEST-1:1 | 测试命令必须 1:1 复现真实事件路径（消息组件/模板/LLM） |

## 增量审查反思（PR #29）

**质量轨迹**：中等偏上 → 良好 → 良好
- 三轮逐步聚焦：发现代码重复 → 解决后又出现语义回归 → 最终闭环
- 三轮均出现"评分略偏高估"问题，源于未验证边界（全部调用点、README 命令名真实性）

**高频遗漏**：
- LLM 失败时的 fallback 行为
- 重构后差异化错误文案/日志标签是否丢失
- 权限校验严重度系统性低估（建议→Minor）
- 未追问"测试命令是否 1:1 复现真实路径"这一灵魂问题

**严重度标尺校准**：
- 涉及群内真实副作用 + LLM 配额 → 至少 Minor，不能 Suggestion
- 用户可见的文档失同步 → 项目标准决定 Blocker/Minor
- 行为语义回归（语气统一化丢失差异化）→ Minor，必要时升 Suggestion

## Issue 分析反思（#28）

**质量轨迹**：差（解析失败兜底为 `other`）→ 良好
- 教训：输出解析失败**不能**退化为空标签/无标题，必须尽力产出
- 标题含显式元信息 `[feature]`/`[low]` 时，必须直接采用而非重新推断
- `good first issue` 置信度应保持谨慎，依赖代码结构是否已模块化

**测试命令类需求关注点**：权限校验、上下文模拟、刷屏/滥用风险、是否仅群聊有效、是否误触发真实事件

**重复检测**：不能只靠命令关键词，需覆盖"测试/预览/模拟/欢迎语/退群/踢出"等语义词

## 工作流备忘

- 增量审查开头先做问题清单一览，再评估本次变更
- 重构型 PR 必问三问：差异化语义是否参数化？容错/错误行为是否改变？副作用面（README/CHANGELOG）是否被波及？
- Issue 分析：尊重显式元信息；标签体系未知时给出通用建议而非留空；可行性可给条件性判断
